# 拠点・素材表示の議事録

- 日付: 2026-09-01
- 結果: 提案を作成する

## 議論した内容

最小端末サイズ `80x24` を維持したまま、現在の拠点と拾得済み素材を常時確認できる2行を追加する。User Choices と Progress をそれぞれ1行縮め、既存の3本の区切り線と Information Log の最小高は維持する。

拠点はタスクの実行場所を表す既存の Location とは別の概念とする。将来、クラフトや技術開発の選択を拠点に結び付ける予定があるため、TUI の固定文言にはせず、Settlement の安定した id と英語ラベル、および現在の Settlement を core の状態として持つ。最初の Settlement は `awakening_shore` / `Awakening Shore` とする。今回は切替操作、クラフト、技術開発までは実装しない。

素材行には、カタログに存在する素材のうち一度でも拾得したものだけをカタログ順で表示する。インベントリの ResourceStack が存在することを拾得済みの印とし、将来素材を消費して個数が0になってもスタックを削除せず表示対象に残す。未拾得の素材しかない間は、素材行に案内文を出さず空行とする。

表示素材数は固定せず、`Label: amount` と区切りの実際の幅から計算する。表示中の先頭素材を ResourceId で保持し、`.` と `,` ではページ単位ではなく素材1件単位で表示開始位置を動かす。個数の桁が変わって一度に収まる件数が変化しても、先頭素材を維持して表示位置の不意な移動を避ける。

左右の `<` と `>` は、その方向に隠れた素材がある場合だけ表示する。境界でも矢印用の幅自体は予約して空白に置き換え、素材本文を左右へずらさない。Global Menu には素材移動、Backspace、終了の案内を常時表示し、その時点で使えない操作は何もしない。

## 確認した質問

1. 拠点は既存の Location と同じ概念か、クラフトや技術開発に使う別の概念か。
2. 拠点行と素材行を加えた画面順、および User Choices と Progress の表示上限低下を許容するか。
3. 素材は未拾得のものや0個のものも表示するか、表示順、1ページの件数、端での移動をどうするか。
4. Settlement を TUI の固定表示にするか、安定 id と現在値を core に持たせるか。初期 Settlement の英語名を何にするか。
5. 固定5件の素材枠で長いラベルを切るか、実際の文字幅から表示件数を計算するか。
6. 個数の桁数によってページ境界が動く問題を許容するか、移動単位を見直すか。
7. 移動不能な境界でも矢印を表示するか、非表示にするか。非表示時に本文位置を維持するか。
8. 素材をまだ拾得していないとき、案内文を表示するか空行にするか。
9. 素材移動と Backspace の案内を Global Menu に表示するか、利用不能時の項目を隠すか。
10. 拾得済み状態をインベントリとは別に管理するか、ResourceStack の存在で表すか。

## 採用しなかった案

- 拠点を既存の Location として扱う案は採用しなかった。Location は Target が Action を実行する場所であり、Settlement は将来クラフトや技術開発の選択を担う発展拠点だからである。
- Settlement 名を TUI に直接埋め込む案は採用しなかった。将来の拠点切替や拠点ごとの機能へつなげるため、core のカタログとゲーム状態に置く。
- 未拾得を含む全素材を0個で表示する案は、議論途中で見直した。一度でも拾得した素材だけを表示し、拾得後は0個になっても残す。
- 素材を1ページ5件に固定して長いラベルを常に切る案は採用しなかった。利用可能な横幅と実際の表示幅から件数を計算し、情報量を増やす。
- `,` と `.` で可変幅のページ全体を送る案は採用しなかった。個数の桁数によってページ境界が動くため、先頭素材をResourceIdで保持し、素材1件ずつ移動する。
- 境界でも `<` と `>` を表示したまま入力だけ無効にする案は採用しなかった。移動可能性を正しく示すため矢印は非表示にする。ただし本文の位置を変えないよう、その幅は予約する。
- 未拾得時に `No materials` と表示する案は採用しなかった。素材行を空行にする。
- 拾得済み素材を別のフラグ集合でも管理する案は採用しなかった。ResourceStack の存在を拾得済み状態として使い、数量が0でもエントリを保持することで重複状態を避ける。
- Global Menu からその時点で利用不能な操作を隠す案は採用しなかった。素材移動と Backspace の案内を常時表示し、利用不能時は何もしない。

## 保留事項

- Settlement の発見、解放、切替操作。
- Settlement に応じたクラフト、技術開発、その他の選択肢。
- 素材の消費処理とインベントリの永続化。
- 5件を超える User Choices または Progress のページングや可変高。
