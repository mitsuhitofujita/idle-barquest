# 複数素材報酬の議事録

- 日付: 2026-09-06
- 結果: 提案を作成する

## 議論した内容

Location と Action の組み合わせごとに合計100%の表から結果を1つ選んでいた報酬モデルを、各報酬エントリを独立に判定するモデルへ変更する。これにより、1回の Action 完了で複数種類の素材を獲得できる。

新しい仕組みは採取や狩りだけに限定せず、すべての Location と Action の報酬に利用できる汎用モデルとする。将来追加するクラフトでは全判定に失敗する可能性があるため、報酬表に100%のエントリが含まれることは必須としない。成功したエントリが一つもなければ、完了結果を `Nothing` として扱う。

同じ素材を一つの報酬表へ複数回定義することを許容する。各エントリを個別に判定し、同じ素材の成功分は合算してインベントリと完了イベントへ反映する。たとえば Pebble x1 のエントリが2件とも成功した場合は Pebble x2 を得る。異なる素材は、報酬表に最初に現れた順序を維持して1行の完了ログへ表示する。

100%のエントリは乱数を消費せず必ず成功させる。100%未満のエントリだけを定義順に1回ずつ抽選する。これにより、乱数は不確実な結果にだけ使用され、テストとシミュレーションで再現する対象が明確になる。

既存の6組の所要時間は10秒のままとし、提示された確率と数量で報酬を置き換える。この変更によって全 Action が少なくとも素材を1個与え、従来は1個だった1回あたりの期待獲得数が組み合わせに応じて1.1個から1.6個へ増えることは意図した調整である。Nearby Woods の Hunt に10%で Tiny Magic Stone x1 を追加し、Resource Catalog にも新しく登録する。

discussion 0007 では、当時の確率表が合計100%で一つの結果を表すものだったため、独立した複数判定を採用しなかった。今回は確定報酬と追加報酬を同時に表すこと、および将来のクラフトで全失敗を表せることが新しい要件となったため、その判断を意図的に見直す。

## 確認した質問

1. 記載された各素材の確率を独立した判定として扱うか。
2. 複数素材を一つの完了イベントと1行の Information Log にまとめるか。
3. 10秒の所要時間、提示された確率、供給量の増加、Tiny Magic Stone の追加を意図した変更として扱うか。
4. 報酬モデル自体は、すべての判定に失敗する表を許容するか。
5. 同じ報酬表に同一素材のエントリを複数定義できるようにするか。
6. 新しい仕組みを採取・狩り専用ではなく、すべての Location と Action で使えるものにするか。
7. 同一素材を合算し、異なる素材を定義上の初出順で表示するか。
8. 100%のエントリでも乱数を消費するか。

## 採用しなかった案

- 排他的な報酬表を維持する案は採用しなかった。1回の Action から確定素材と追加素材を同時に得る要件を表現できないためである。
- 各報酬表に100%のエントリを必須とする案は採用しなかった。将来のクラフトではすべての判定に失敗する可能性があるため、成功結果が空になることをモデルとして許容する。
- 同一素材を報酬表内で一意に制限する案は採用しなかった。同じ素材の複数エントリが成功したときに数量を合算し、Pebble x2 のような結果を表現するためである。
- 100%のエントリでも乱数を消費する案は採用しなかった。結果が確定している判定で乱数列を進める必要がなく、シミュレーション結果を余分に変動させるためである。
- クラフトそのものを今回実装する案は採用しなかった。報酬モデルは将来のクラフトに利用できる形にするが、クラフトの入力、消費、成功条件、UI は別の議論で扱う。

## 保留事項

- クラフトの入力素材、消費タイミング、成功・失敗条件、および UI。
- ステータス、道具、Location などによる報酬確率の補正。
- 素材の用途に基づく供給量と所要時間の再調整。
