# ターミナル表示スタイル変更の議事録

- 日付: 2026-08-29
- 結果: 提案を作成する

## 議論した内容

タイトルを3行のASCIIアートへ変更し、プログレスバーの未完了部分をハイフンではなく空白で表現する案を検討した。

確認の過程で、提示されたタイトルは上下行が38文字、中央行が37文字であり、そのまま行単位で中央揃えすると右端が揃わないことが分かった。中央行のタイトル後の空白を1つ増やし、全行を38文字に揃えることとした。

タイトルを1行から3行へ増やすと縦方向の表示領域を消費するため、最小端末サイズとログ領域への影響を確認した。最小端末サイズは現在の `80x24` を維持し、ログ領域が狭くなることを許容する。さらに、タイトル直下にある既存の全幅区切り線は残さず、タイトル下段の装飾を境界として使う。結果として、現行レイアウトと比べたログ領域の減少は差し引き1行となる。

タイトルの横方向は端末幅に追従させず、38文字固定のまま画面中央へ配置する。

プログレスバーは未完了部分だけを空白に置き換える。完了部分の `=`、進行位置の `>`、外枠の角括弧、右側の百分率は維持するため、正確な進捗は引き続き文字情報で確認できる。

## 確認した質問

1. 長さの異なるタイトル中央行を38文字に修正してよいか。
2. 3行タイトルに合わせて最小端末サイズを `80x26` に引き上げるか、`80x24` を維持してログ領域の減少を許容するか。
3. タイトルを38文字固定で中央表示するか、端末幅に合わせて装飾を伸縮させるか。
4. タイトル下段の装飾に加えて、既存の全幅区切り線も残すか。
5. 「引き下げ」が、最小端末サイズの縮小とログ領域の縮小のどちらを意味するか。

## 採用しなかった案

- 中央行を37文字のまま使う案は、上下行と右端が揃わないため採用しなかった。
- 最小端末サイズを `80x26` に引き上げる案は採用せず、既存の `80x24` 対応を維持する。
- 端末幅に合わせてタイトルのコロン部分を伸縮させる案は、提示された意匠を一定に保つため採用しなかった。
- タイトル直下の全幅区切り線を残す案は、タイトル下段の装飾と境界表現が重複するため採用しなかった。
